# Telegram-бот для InvenTree: проект

Задача: сотрудник фотографирует прибор, а бот сам распознаёт производителя, модель и серийный номер, находит или создаёт карточку в InvenTree, присваивает внутренний номер, прикладывает фото и мануал. От человека требуется только сфотографировать и подтвердить.

## Главный сценарий: «сфоткал — подтвердил»

```
/add
 └ бот: «Где вы?» → кнопки: Ровесник / Дорожка / …  (запоминает последнее место)
 └ бот: «Место?» → Сцена 2 / Офис / …
 └ сотрудник: 1–3 фото (шильдик + общий вид)
 └ бот (5–10 сек):
      Pioneer DJ XDJ-1000MK2
      S/N: VJXK012345  ✓ совпал со штрихкодом
      Категория: DJ-оборудование / Проигрыватели
      В этом месте есть непроверенная позиция из райдера (1 шт.)

      [✅ Подтвердить]  [✏️ Исправить]  [➕ Новая позиция]
 └ ✅ → бот:
      • берёт 1 шт. из позиции райдера и превращает её в отдельную позицию с серийником
      • присваивает внутренний номер P2P-00042
      • ставит статус OK
      • прикладывает фото шильдика к позиции, общий вид ставит картинкой модели (если её нет)
      • присылает этикетку с QR для печати
      «Готово: P2P-00042. Следующий прибор?»  ← место запомнено, можно сразу фотографировать
```

Если модели ещё нет в InvenTree, бот предлагает категорию (кнопками из дерева), создаёт деталь, привязку к производителю и запускает поиск мануала в фоне.

Поиск и действия с существующим:

* **Фото QR-этикетки или текст серийника / P2P-номера** → карточка позиции с кнопками: «Переместить», «В ремонт», «Списать», «Добавить фото», «Мануал».
* **/move** → отсканировал несколько этикеток подряд → выбрал новое место → всё перемещено одной операцией (история перемещений остаётся в InvenTree).

## Распознавание: как устроено

Нужно надёжно прочитать текст и не ошибиться в серийнике. Поэтому три слоя:

1. **Декодирование штрихкодов** (библиотека `zxing-cpp`). На шильдиках часто есть штрихкод или QR с серийником. Декодер читает его точно, без угадывания.
2. **Claude (распознавание изображений).** Фото уходит в модель вместе со списком наших категорий и известных моделей. Ответ приходит строго по JSON-схеме (structured outputs):
   ```json
   {"manufacturer": "Pioneer DJ", "model": "XDJ-1000MK2", "serial": "VJXK012345",
    "category": "DJ-оборудование / Проигрыватели", "confidence": "high",
    "notes": "на шильдике также 100-240V 50/60Hz"}
   ```
   Модель читает и мелкий текст, и кривые фото, и узнаёт прибор по внешнему виду, если шильдика не видно. Классический OCR (Tesseract и подобные) выдаёт просто кашу из текста с шильдика, и отдельно приходится разбирать, где модель, а где серийник. Здесь эта работа не нужна.
3. **Сверка и подтверждение.** Если серийник из штрихкода и из текста совпали, ставится ✓. Если нет или штрихкода нет, бот явно просит проверить серийник. В базу ничего не пишется без нажатия «Подтвердить». Фото шильдика всегда прикладывается к позиции, так что любую ошибку можно перепроверить позже.

Сопоставление с каталогом: нормализация названий (`aliases.yaml` из импорта райдеров) плюс нечёткий поиск (`rapidfuzz`), так что «XDJ1000 MK2» и «XDJ-1000MK2» находят одну деталь.

Перед отправкой фото сжимается и поворачивается по EXIF (Pillow), чтобы не платить за лишние пиксели.

Модель по умолчанию: `claude-opus-5-5`. Если окажется, что более дешёвая модель на наших фото распознаёт так же хорошо, переключимся. Проверим это на 20–30 реальных фото шильдиков, прежде чем что-то менять.

## Внутренние инвентарные номера

Предложение:

* У каждой единицы техники есть **внутренний номер** вида `P2P-00042`: сквозной, уникальный, не зависит от заведения (техника переезжает, а номер остаётся).
* Он записывается в поле **Serial** позиции InvenTree и печатается на QR-этикетке. Поиск по нему встроенный.
* В InvenTree включается настройка «серийники уникальны глобально». Номера выдаёт бот: берёт максимальный существующий и прибавляет 1. Если нужно, чтобы так же работало и ручное создание в InvenTree, добавим в наш плагин `ValidationMixin` с правилом формата и увеличения номера.
* **Заводской серийник** хранится отдельно. Варианты:
  * а) поле **Batch** («партия»). Оно видно в таблицах и по нему работает поиск, но название поля не по смыслу;
  * б) свой параметр/метаданные позиции. Корректно по смыслу, но в интерфейсе виден хуже.

  Рекомендую (а) с договорённостью «Batch = заводской S/N».
* Для мелочи без смысла учитывать каждую штуку (кабели, стойки) внутренний номер не нужен: она остаётся количеством.

## Мануалы

Фоновый обработчик в том же сервисе. Он срабатывает, когда бот создаёт новую деталь, и раз в сутки проходит по деталям без мануала.

1. Сначала справочник страниц загрузок по производителям (Pioneer DJ, Yamaha, Behringer, Epson, …).
2. Если там нет, то Claude с серверным **веб-поиском**: «найди официальный PDF руководства пользователя для <производитель> <модель>, предпочтительно на русском, иначе на английском». Модель возвращает URL-кандидаты.
3. Проверка: скачивается PDF, первая страница отправляется в модель с вопросом «это руководство именно к этой модели?».
4. Мануал прикладывается к детали ссылкой или файлом (это решение из PLAN.md, этап 4). В чат приходит уведомление «Найден мануал для XDJ-1000MK2».

Команда `/manual <модель>` запускает поиск вручную и показывает, что нашлось.

## Пользователи и права

* Каждый сотрудник один раз привязывает свой аккаунт InvenTree: `/login` → логин и пароль → бот получает **личный** API-токен и удаляет сообщение с паролем из чата. Тогда в истории InvenTree видно, кто что добавил или переместил, и работают права групп.
* Без привязки бот ничего не делает. Плюс белый список Telegram ID на всякий случай.

## Технологии и развёртывание

| Часть | Что используем |
|---|---|
| Бот | Python, `aiogram` 3 |
| InvenTree | REST API (наш `inventree_client.py`, расширенный) |
| Распознавание и поиск мануалов | Anthropic Python SDK, Claude с vision, structured outputs и веб-поиском |
| Штрихкоды и QR | `zxing-cpp` |
| Фото | `Pillow` |
| Нечёткий поиск | `rapidfuzz` |
| Состояние | SQLite: привязки пользователей, последнее место, очередь мануалов |
| Запуск | Docker-контейнер рядом с InvenTree (тот же `docker compose`) |

Секреты (токен Telegram-бота, ключ Claude API) хранятся в `.env` на сервере, в git не попадают.

Важно: Claude API доступен только из поддерживаемых стран, поэтому сервер с ботом должен находиться в такой стране. Если InvenTree стоит на зарубежном VPS, бот кладём туда же.

## Этапы

1. **MVP** — `/login`, выбор места, фото → распознавание → подтверждение → создание или сериализация позиции, внутренний номер, фото во вложения.
2. **Работа с существующим** — поиск по фото QR / серийнику, перемещение, смена статуса, пакетное перемещение.
3. **Мануалы** — фоновый поиск и `/manual`.
4. **Этикетки** — бот присылает PNG-этикетку или отправляет её на принтер через плагин печати InvenTree.
