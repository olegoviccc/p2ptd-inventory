# Итоги сессии: интеграция с InvenTree

Ветка: `claude/zen-archimedes-oqoew7`. Сервер InvenTree: https://p2ptd-inventory.online (последняя версия).

## Что сделано

### 1. План работ — `docs/PLAN.md`
Этапы: импорт по райдерам → обход и серийники → этикетки → распознавание по фото → мануалы.

### 2. Импорт оборудования из райдеров
- Разобраны райдеры **Ровесника, Дорожки, Пешки, Номера** → `data/riders/*.yaml` (исходники в `data/riders/source/`). В итоге 14 производителей, 41 модель, 73 позиции на складе, 137 единиц.
- `import_stock.py` создаёт производителей, детали, модели производителей (MPN) и позиции на складе со статусом «Требует внимания». Скрипт можно запускать повторно без дублей, есть режим `--dry-run`.
- `inventree_client.py` — общий клиент. Адрес и токен берутся из `.env` (в git не попадает). Поддерживаются файлы с BOM и `.env.txt` (Windows).
- В дерево категорий добавлена категория «Свет / Дым и эффекты».
- **Импорт у пользователя прошёл успешно.**

Исправлено по ходу:

| Проблема | Причина | Решение |
|---|---|---|
| «не задан адрес» при заполненном `.env` | Блокнот Windows сохраняет файл с BOM | чтение в `utf-8-sig`, поддержка `.env.txt` |
| 403 на `/api/company/` | производители относятся к правилу Purchase Order | проверка прав до начала, понятное сообщение |
| 400 «Select a valid choice» | MPN привязывается только к покупной детали | детали создаются с флагом Purchaseable |

### 3. Android-приложение `p2p-inventory`
- GitHub Actions (`.github/workflows/android-app.yml`) собирает официальное приложение InvenTree со своим названием и своим `applicationId` (ставится рядом с официальным) и с отключённой отправкой ошибок в Sentry разработчиков InvenTree.
- Тестовая сборка прошла. Для выпуска нужно влить ветку в `main` и добавить 4 секрета с ключом подписи (`docs/ANDROID.md`).

### 4. Telegram-бот — `bot/`, `docs/BOT.md`
- **Сценарий:** «🔑 Войти» (свой аккаунт InvenTree) → «➕ Добавить прибор» → место (запоминается) → 1–3 фото → распознавание → карточка → «✅ Сохранить».
- **При сохранении:** внутренний номер `P2PTD-00001` в поле Serial, заводской S/N в поле Batch, одна единица списывается из позиции райдера, фото уходят во вложения, общий вид ставится картинкой модели, бот присылает PNG-этикетку с QR.
- **Распознавание:** штрихкоды (`zxing-cpp`) для проверки серийника и модель с компьютерным зрением с ответом строго по JSON-схеме. Движки: Claude (`claude-opus-5-5`, effort `low`) или своя модель через OpenAI-совместимый API, можно цепочкой `local,claude`.
- **Поиск:** по номеру P2PTD, заводскому S/N или фото QR-этикетки.
- **Интерфейс:** все действия кнопками, отмена и «назад» на каждом шаге.
- **Логи:** файл `bot_data/logs/bot.log` с ID пользователя и временем обработки, пароль скрыт. Журнал действий в SQLite открывается у администраторов кнопкой «📜 Журнал». Об ошибках приходит уведомление администраторам.
- **Скорость:** общий пул соединений, кэш каталога, фото обрабатываются при получении, запросы к InvenTree идут параллельно.
- **Тесты:** 16 тестов (`tests/`), в том числе сквозной сценарий через настоящие обработчики aiogram. Проходят локально и в CI. Тесты нашли и помогли исправить ошибку с кэшем после перезагрузки сервера.

### 5. Обсуждено
- **Плагины InvenTree:** печать этикеток (Brother, Zebra, CUPS), уведомления через Apprise, свои статусы, шаблоны отчётов (например, автоматический райдер заведения). Форк InvenTree делать не стоит, всё решается своим плагином.

## Принятые решения

- Модели оборудования вносятся вручную или ботом; Excel-шаблон не нужен.
- Позиции без модели из райдеров записываются как есть.
- Внутренний номер — `P2PTD-00001`, сквозной, не зависит от заведения.
- Заводской серийник хранится в поле Batch.
- У каждого сотрудника свой аккаунт InvenTree.
- Название приложения — `p2p-inventory`, иконка официальная.

## Что осталось / открытые вопросы

1. **Сервер для бота:** где хостится InvenTree. Claude API работает только из поддерживаемых стран.
2. **Ключи:** токен бота от @BotFather и ключ Claude API, вписать в `.env` на сервере.
3. **Своя модель:** какая модель и на чём запущена (нужна модель с компьютерным зрением и OpenAI-совместимый API, плюс туннель до компьютера).
4. **Первый запуск бота** на настоящих InvenTree и Telegram. Пока проверено только тестами.
5. **Android:** влить ветку в `main`, создать ключ подписи, запустить сборку.
6. **По райдерам:** 4 или 5 караоке-комнат в Номере, заводить ли зоны трансляции Ровесника отдельными местами, райдеры Скрепки и Гаража.
7. **Следующие этапы:** поиск мануалов, перемещение и смена статуса из бота, печать этикеток на принтер.
